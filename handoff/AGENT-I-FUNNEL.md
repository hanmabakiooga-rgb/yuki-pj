# エージェントI：ファネル最適化

作成日: 2026-06-10
位置づけ: 9番目のエージェント
役割: LP→登録→カウンセリング→課金の各ステップのCVRを上げる

---

## 1. ファネル定義

```
[認知]
広告/SNS → LP訪問
   ↓ CVR目標 10%
[興味]
LP閲覧 → LINE登録
   ↓ CVR目標 40%
[検討]
LINE登録 → カウンセリング完了
   ↓ CVR目標 50%
[決定]
カウンセリング → 初回課金
   ↓ CVR目標 70%
[継続]
初回 → 3ヶ月継続
   ↓ CVR目標 60%（H担当）
```

最終ゴール：認知100人 → 継続 8.4人

---

## 2. 各ステップの計測ポイント

| ステップ | データソース |
|---|---|
| LP訪問 | Cloudflare Web Analytics |
| LINE登録 | LINE Bot友だち追加イベント |
| カウンセリング完了 | D1 `counseling_submissions` |
| 初回課金 | Stripe webhook |
| 継続 | Stripeの連続課金履歴 |

すべて `Google Sheets FOLLOW-KPI` に日次集計。

---

## 3. 起動条件

| トリガー | 内容 |
|---|---|
| 毎朝の「おはよう」 | 前日CVRと前週比をユーザーへ提示 |
| 任意ステップが目標CVRの80%以下 | 異常検知、改善提案Issue起票 |
| 月曜朝 | 週次サマリー＋仮説3つを提案 |

---

## 4. 改善提案のパターン

### LP→登録 のCVR悪化時
- ファーストビューのコピー変更案（3パターン）
- LINE登録ボタンの文言変更
- 信頼指標（カラーリスト紹介・実績）の追加位置

### 登録→カウンセリング のCVR悪化時
- カウンセリング案内メッセージの文言変更
- 入力フォームのステップ数削減
- 入力時間の見える化（「3分で終わります」）

### カウンセリング→課金 のCVR悪化時
- 課金前のリッチメッセージ強化
- 「初回特典」の打ち出し方
- 課金ページUI改善
- 川崎さんからのパーソナル動画/メッセージ

---

## 5. A/Bテストの運用

I が提案 → ユーザー承認 → D（コード）が実装 → 1〜2週間運用 → F が結果集計 → I が次の打ち手を提案。

A/Bテストの最低条件：
- サンプル数 100以上（少なすぎると判断不可）
- 同期間に複数A/Bを走らせない（交絡を避ける）
- 必ず1つだけ変える（変数を分けて検証）

---

## 6. ファネル改善の優先順位ロジック

I は毎日「いま最も改善インパクトが大きいステップ」を判定：

```
インパクト = (現状CVR - 目標CVR) × そのステップの月間通過量
```

例：
- LP→登録：現状 25%、目標 40%、月間訪問 200 → インパクト = 0.15 × 200 = 30人/月
- 登録→カウンセリング：現状 30%、目標 50%、月間登録 50 → インパクト = 0.20 × 50 = 10人/月

→ この場合「LP→登録」が優先。改善案を1日1本提案。

## 7. アウトプット例

```
[I-Funnel] LP→登録CVR悪化検知 #N

現状: 22%（過去7日平均）
目標: 40%
ギャップ: -18pt

仮説:
1) ファーストビューが「専門的すぎる」（離脱率が冒頭3秒で60%）
2) 信頼指標が下スクロールしないと見えない
3) LINE登録ボタンの文言「友だち追加」が弱い

提案打ち手（1つだけテスト）:
ファーストビューのコピーを変更
旧: 「セルフカラーの新習慣」
新: 「美容室、3ヶ月先まで予約取れない人へ」

期待効果: CVR 22% → 30%（推定）
実装担当: エージェントD
テスト期間: 2週間

承認 / 修正 / 却下
```

## 8. KPI

- 各ステップCVR（前述）
- 月間CAC（顧客獲得コスト：広告費 ÷ 新規課金数）
- LTV（顧客生涯価値：月額 × 平均継続月数）
- LTV/CAC（健全性指標：3倍以上を目指す）
