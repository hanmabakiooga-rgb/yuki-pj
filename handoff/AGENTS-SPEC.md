## 1. 共通仕様

### 1-1. 各エージェントの入出力

| 項目 | 内容 |
|---|---|
| **入力** | 状態ストア（GitHub Issues / D1 / KPI Sheet）を読む |
| **処理** | 専門ドメインの判断・生成 |
| **出力** | GitHub Issue（ラベル `approval-queue` 付き）として承認キューに積む |
| **実行** | ユーザーが承認したら、対応するアクションを発動 |

### 1-2. 状態ストア

| ストア | 内容 |
|---|---|
| GitHub Issues | 承認キュー / 各エージェントのバックログ |
| D1（line-harness） | 顧客・カウンセリング・送信ログ |
| Google Sheets `FOLLOW-KPI` | 登録数 / サブスク数 / 解約 / 広告費 / CPA |
| R2 | 画像・PDFアセット |

### 1-3. 承認キューのIssueフォーマット

```markdown
[A-SNS] X投稿案 #N

## 内容
（投稿本文）

## 添付
（画像URL / 動画URL）

## 公開予定
2026-06-11 19:00

## 承認操作
- 承認 → ラベル `approved` を付与（自動投稿）
- 却下 → ラベル `rejected`
- 修正依頼 → コメントで指示
```

## 2. エージェントA：SNS生成

### 役割
HEJ（@hej.haircolor.treatment.rab・既存781フォロワー）と FOLLOW公式（@kokodake2026・新規）の2アカウント体制で、Threads / Instagram Feed / Reels / note の投稿案を作成。

詳細なアカウント役割分担・自動化仕様は `handoff/SNS-STRATEGY-FINAL.md` を参照（最上位判断基準）。

### 3つの運用モード（SNS-STRATEGY-FINAL.md §7 準拠）

#### モードA: HEJ-Threads（手動または半自動）
- 対象アカウント: **HEJ**（@hej.haircolor.treatment.rab）
- 頻度: 週3-4投稿
- トーン: 川崎個人の声、業界話・哲学・カラー知識
- リズム: 2日に1回 FOLLOW誘導投稿を混ぜる（月・水・金・日）、火・木・土は業界話
- 承認: 川崎さんレビュー必須

#### モードB: 両アカウントReels（手動）
- 対象アカウント: **HEJ** と **FOLLOW公式** 両方
- 同じ動画ベースに、**冒頭2秒と末尾2秒（CTA）だけ差し替え**た2本を出力
  - HEJ用: 冒頭「20年カラーリストが教える本音」／末尾「DMで質問OK」「プロフからFOLLOW」
  - FOLLOW公式用: 冒頭「分け目だけ、染めればいい」／末尾「月880円・写真送るだけ・プロフのLINEから」
- 編集: Vrew/CapCut

#### モードC: FOLLOW-Threads（完全自動化）
- 対象アカウント: **FOLLOW公式**（@kokodake2026）
- 頻度: **1日3投稿**（朝7:30 / 昼12:30 / 夜21:00 JST）
- 生成タイミング: 毎晩23:00 に翌日3投稿分を生成
- フロー: A生成 → E法務チェック自動 → 合格分のみ D1 `sns_queue` に「scheduled」保存 → Workers Cron が Threads API で投稿
- 投稿内容の配分:
  - 朝7:30 → 教育・実践（薬剤の使い方・頭皮ケア知識・季節対策）
  - 昼12:30 → 共感・コア訴求（気になるところだけ／月880円／FOLLOW案内）
  - 夜21:00 → 川崎さんの哲学・利用者の声・呼びかけ
- 管理者LINEには「明日の3投稿」サマリーのみ届く（中身は事後ログで確認）
- 緊急停止: 管理者LINEから `stop_auto_posting` コマンド、または異常検知（同一文言3回連続・API失敗）で自動停止
- 関連D Issue: #8（Threads自動投稿パイプライン）/ #9（sns_queue D1テーブル + 管理画面）

#### モードD: note（川崎個人、月1-2本）
- 対象アカウント: HEJプロフから誘導
- 川崎さんの編集レビュー必須

### 起動条件
- 毎日朝の「おはよう」で当日＋翌日2日分を生成（モードA・B）
- 毎晩23:00に翌日分3投稿を自動生成（モードC）
- バックログが3日分を下回ったら追加生成

### 入力
- 直近の競合動向（coloris.shop / 美容室系発信）
- 既存投稿のエンゲージメント（後で実装）
- 季節・髪悩みカレンダー（梅雨→広がり、夏→退色、秋→白髪気になる、等）

### 出力
- X：280文字以内、ハッシュタグ最大3個、画像1枚または動画15秒
- Instagram：キャプション最大1,000文字、画像1枚（カルーセル最大3枚）

### NGワード（必ずチェック）
- 全額返金 / 効果保証 / 100%染まる / 美容室不要 / 誰でも安全 / ブリーチ毛でも安心
- 薬機法・景表法に抵触する効能効果の断定

### コアメッセージ（POSITIONING-FINAL.md §11 確定版 7軸）
1. **「気になるところだけを染める」**（全頭ではない、最小限）
2. **「プロ用商材で安全に」**（市販品ではなく、美容師が現場で使うもの）
3. **「頭皮ケアまで月単位で伴走」**（染めて終わりじゃない）
4. **「20年 × 何万人 × 大阪専門店 × 海外経験 × 現役」の権威性**（川崎さんの実績）
5. **「染める/染めないも一緒に判断」**（押し付けない・「染めない美容師」とは違う）
6. **「月880円、いつでも解約OK」**（敷居の低さ）
7. **「商材購入は任意・他で買ってもOK」**（押し売りしない）

### 必ず参照する一次情報源（優先順）
1. `handoff/POSITIONING-FINAL.md`（**最終判断基準**、全出力の合否はここで決まる）
1. `handoff/SNS-STRATEGY-FINAL.md`（**最終判断基準**、アカウント運用・3モードの仕様はここで決まる）
3. `handoff/KNOWLEDGE-BASE/` 配下の全ファイル（投稿の根拠）
4. `handoff/agent-outputs/G-competitive-intel-2026-06-10.md`（競合と空白市場）
5. `handoff/agent-outputs/G-trend-report-2026-06-10.md`（SNSアルゴリズム）

ナレッジベースに無い情報は「推測しない」「触れない」「ユーザーに追加依頼」のいずれかを選ぶ。  
POSITIONING-FINAL.md §11 の7軸に反するコピーは**全エージェント・全レビューで自動却下**。

### 承認後アクション
- X：`x-api` または手動投稿（初期は手動）
- Instagram：手動投稿（API承認待ち）

## 3. エージェントB：LINE返信ドラフト

### 役割
顧客からのLINE問い合わせに対する**返信案**を生成。最終送信は川崎さん（カラーリスト）または承認後Bot。

### 起動条件
- 顧客からのLINE着信を検知（既存webhook経由）
- 「おはよう」時に未返信メッセージを一括処理

### 入力
- メッセージ本文
- 過去のやり取り（消費上限：直近10件）
- 顧客のステータス（D1）
- カウンセリング回答（あれば）

### 出力
- 返信案2バリアント（A：丁寧フォーマル / B：親しみカジュアル）
- 緊急度ラベル（高：頭皮トラブル/染めるかの判断、中：相談、低：雑談）

### NG動作
- 医学的診断（皮膚科への誘導文言を必ず添える）
- 「絶対大丈夫」「染まります」など断定
- 価格・解約条件の独自解釈

### 承認後アクション
- 川崎さん経由：承認後に川崎さんのLINEへ案を転送
- Bot経由（雑談・自動返信OK枠）：そのまま顧客に push

## 4. エージェントC：広告台本

### 役割
Meta広告（Instagram/Facebook）の動画台本・静止画コピー案。

### 起動条件
- 週1回、月曜朝に新台本3本生成
- CPA悪化を検知したら緊急生成

### 入力
- 直近の広告KPI（リーチ/CTR/CPA/CVR）— Google Sheets `FOLLOW-KPI` から読む
- 季節・髪悩みカレンダー
- 競合の広告動向（Meta広告ライブラリ手動チェック）

### 出力（1本ずつ）
- フック（最初の3秒）
- ボディ（15〜30秒）
- CTA（行動喚起）
- ターゲット設定案（年齢/興味/地域）
- 想定CPA

### 予算ガード
- **月予算3万円**を絶対超えない
- 1日1,000円が上限、3日連続でCPAが目標の2倍を超えたら自動停止勧告

### 承認後アクション
- 台本承認 → 撮影/編集タスクをエージェントAのIssueに連動
- 配信設定承認 → Meta広告マネージャで手動入稿（初期）

## 5. エージェントD：コード

### 役割
リポジトリへの実装・修正PR作成。

### 起動条件
- 「おはよう」時にエージェントF（分析）から提案された改善Issueを処理
- ユーザーから直接コードタスクが入った時

### 入力
- GitHub Issue（ラベル `code-task`）
- リポジトリの現状コード

### 出力
- ブランチ作成 → 実装 → typecheck/test → PR作成
- PR本文に「変更内容 / 影響範囲 / テスト結果 / マージ後の手順」を必ず記載

### 守るルール
- secret はコミットしない
- 既存テストを壊さない
- PRサイズは「1機能=1PR」、大きすぎたら分割
- 本番デプロイ・本番D1 migration はユーザー承認後

### 承認後アクション
- PR マージ → 自動デプロイ（Cloudflare Pages/Workers 連携）

## 6. エージェントE：法務審査

### 役割
すべてのアウトプット（SNS/LINE/広告/同意書/LP）に対する**法令チェック**。

### 起動条件
- A/B/C/Dのエージェントが出力する直前に必ず通す（ゲート）
- ユーザーが直接「これチェックして」と投げた時

### チェック対象法令
- 薬機法（効能効果の不当表示）
- 景表法（優良誤認・有利誤認）
- 特商法（通信販売・継続課金の表示）
- PIPA（個人情報保護法）
- LINE公式アカウント規約

### 出力
- 判定：OK / 修正必要 / NG
- 該当箇所と理由
- 修正案（あれば）

### NG例の例示
- 「染まります」→「染まりやすい設計です」
- 「アレルギー安心」→「アレルギーが心配な方の相談を受けています」
- 「いつでも100%返金」→「いつでも解約できます」

### 承認後アクション
- 通常はゲートとして動作（承認不要）
- ユーザー判断要の論点はIssueとして承認キューに積む

## 7. エージェントF：分析

### 役割
KPIモニタリングと改善提案。

### 起動条件
- 毎日朝「おはよう」で前日KPIを集計
- 週次サマリーを月曜朝に出力

### 入力
- Google Sheets `FOLLOW-KPI`
- D1（登録/サブスク/解約/送信ログ）
- LINE Bot の友だち数
- 広告KPI（手入力 or API）

### 出力
- 当日サマリー（前日数値・前日比・週累計）
- 異常検知（CPA悪化/解約率上昇/エンゲ低下）
- 改善提案（エージェントA/C/Dへタスク化）

### KPIゴール再掲
- 1ヶ月：LINE登録 →100名 / サブスク →30名
- 1年：サブスク →5,000名
- 広告：月3万円以内

### 承認後アクション
- 提案 → 該当エージェントのバックログIssueに変換

## 8. 起動・終了の挨拶

### 朝「おはよう」
1. Fが前日KPIサマリーを生成 → 管理者LINEへ送信
2. A/B/C/D を並列発火
3. 承認キューに積まれたIssueを管理者LINEへFlex Messageで送信
4. ユーザーの承認操作を待機

### 夜「おつかれ」
- 当日承認・実行されたものの一覧
- 翌日朝の予定ジョブ一覧
- 未承認の繰越Issue
- 次の意思決定が必要な論点（ユーザーへの問い）

---

## 9. 初期は手動承認、徐々に自動化

| 期間 | 自動化レベル |
|---|---|
| Week 1〜2 | 全件ユーザー承認（信頼を積む） |
| Week 3〜 | 雑談LINE返信・SNS下書きの軽微な修正は自動 |
| Month 2〜 | 広告予算の日次微調整（±20%まで）も自動 |
| ずっと手動 | 支払い / 大型意思決定 / 個別ケース判断 |
