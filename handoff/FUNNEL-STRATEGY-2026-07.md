## L1. 認知：Threads自動投稿の内容向上

### 現状（実機確認済み 2026-07-01）
- GAS + Buffer (shareNow) で 1日3投稿（朝7:30/昼12:30/夜21:00）稼働中
- **`USE_AI_GENERATION=false`** — 現在はテンプレ21件のローテーション運用（フェーズ1）
- `ContentGenerator.gs` にAI生成IF実装済み、`ANTHROPIC_API_KEY` 設定済み、`Knowledge.gs` + KNOWLEDGE-BASE 13ファイル完備
- `ImpressionFetcher.gs` / `Analytics.gs` 実装済み（フィードバックデータは取得可能）

### 問題
テンプレ21件 × 3投稿/日 = **7日で全テンプレ消費**。1ヶ月で同じ投稿が4回転し、フォロワーゼロからの新規獲得エンジンとしては弱い。マンネリ化とThreadsアルゴリズムからの減点リスク。

### 施策（優先順）

#### T-1. AI生成モードON（フェーズ2移行）— 今週
```
USE_AI_GENERATION=true に切替
→ ContentGenerator が KNOWLEDGE-BASE 13ファイル + sns_templates をシードに
  毎晩23:00に翌日3投稿を新規生成
→ E法務チェック（LegalCheck.gs）合格分のみ sns_queue へ
→ 不合格時はテンプレにフォールバック（既存挙動）
```
- 切替手順: GAS Script Properties で `USE_AI_GENERATION` を `true` に変更するだけ
- **最初の3日間は毎朝 sns_queue を目視確認**（管理者LINEサマリーで届く）。品質が安定したら通常運用へ
- コスト目安: 3投稿/日 × Claude API ≒ 月数百円レベル

#### T-2. インプレッション・フィードバックループ — 今週から毎週
```
ImpressionFetcher が投稿別閲覧数を sns_log に記録
→ 週1回 Analytics.gs 集計で「テーマ別の勝ち負け」を判定
→ 勝ちテーマの生成比率を翌週上げる（ContentGenerator のテーマ重み）
```
- 判定基準（初期値）: 閲覧数中央値の2倍以上 = 勝ち、半分以下 = 負け
- 負けテーマは書き方を変えて再挑戦（テーマ自体は3週は捨てない）

#### T-3. フック（1行目）強化 — AI生成プロンプトに組込み
Threadsは1行目で止まるかが全て。生成プロンプトに以下パターンをローテーション指定:
- 数字フック「白髪染め、月1回やめて月880円にした話」
- 質問フック「分け目の白髪、鏡見るたび気になりませんか」
- 意外性フック「美容師が『毎回全部染めなくていい』と言う理由」
- 当事者フック「40代になって、美容室の予約が一番のストレスになった」

#### T-4. CTA設計の見直し
- 昼12:30の投稿（共感・コア訴求）のみ明示CTA「プロフィールのLINEから」
- 朝・夜は **CTAなし**（教育・哲学に徹する）→ アルゴリズム減点回避
- プロフィールの LINE リンク (lin.ee/9IC32LC) に **Threads専用の計測パラメータ付きリンク**を検討（lin.ee はUTM不可のため、LINE公式の「あいさつメッセージ→流入元アンケート1タップ」で代替計測）

#### T-5. HEJ→FOLLOW誘導リズム維持（既存戦略のまま）
- HEJ (781フォロワー/97万閲覧) から2日に1回FOLLOW言及
- HEJの権威 → FOLLOW公式フォロー → LINE の2段導線

## L2. 興味：LP・CTA導線

### 現状
- V0改修反映済み（権威性セクション+利用者の声）、CVR推定30-38%
- **LP→LINE登録のCVR計測が存在しない**（最優先で解消）
- LP V2 素材待ち: icons/v2 29個 + cta/ 6個 → 配置後 CODEX 投入（LP-V2-CODEX-PROMPT.md 準備済）
- 川崎写真: 撮影待ち。差し込みは3行修正のみ（KAWASAKI-PHOTO-INTEGRATION.md 準備済）

### 施策（優先順）

#### P-1. CVR計測の設置 — 今週・LP V2より先
```
Cloudflare Web Analytics を follow-lp に設置（GA4不要、Dに依頼 or CODEX）
+ 全CTAボタンに data-cta 属性（位置別: fv / mid-price / mid-cost / pre-faq / faq / footer）
+ クリックイベントを beacon で記録
```
**理由: V2を先にやると「V2の効果」が永遠に測れない。計測→V2の順番は死守。**

#### P-2. LP V2 ビジュアル刷新 — 素材到着次第
- 手順は LP-V2-CODEX-PROMPT.md の通り（§1素材配置 → §2 CODEX投入 → §3検証）
- CTA 6箇所配置（FV「分け目だけ、LINEから相談」〜フッター）
- 期待CVR: 30-38% → 38-48%

#### P-3. 川崎写真差し込み — 写真到着次第（V2と独立に実行可）
- KAWASAKI-PHOTO-INTEGRATION.md の通り。追加CSS不要を検証済み

#### P-4. ファーストビューA/Bテスト — V2安定後（8月）
- 「リタッチ専用」訴求 vs 「880円」訴求 vs 「個別相談」訴求
- Cloudflare計測が入っていれば判定可能。1テスト1週間〜3週間

#### P-5. スクロール70%ポップアップ — 8月（効果検証つき）
- 「LINEで質問だけでもOK」の軽いオファー
- うざさとのトレードオフがあるため、CVR悪化したら即撤去

### L2 KPI
| 指標 | 現状 | 目標 |

| LP→LINE登録CVR | 計測開始 | 40% |

## L3. 転換：LINE → カウンセリング → Stripe課金（最重要レイヤー）

**カウンセリング→課金 28% が全ファネル最大の出血点。ここの改善が最も会員数に直結する。**

### 施策（優先順）

#### S-1. 課金導線メッセージの再設計 — 今週（実装コストゼロ・効果最大候補）
カウンセリング完了後の川崎さんメッセージを再構成:
```
現状: レビュー → 提案 → 「課金リンクを送ります」
改善: レビュー → 「あなた専用の提案」を先に1つ具体的に見せる
      → 提案の続きはサブスク内で → 課金リンク
      → 「いつでも解約OK・追加料金なし」を リンクの直前に置く
```
- B（LINE返信テンプレ）と E（法務）で文言確定 → 即日適用可能

#### S-2. Stripe Checkout の最適化 — 今週〜来週
| 項目 | 現状 | 改善 |
|---|---|---|
| 決済手段 | カード | **+ Apple Pay / Google Pay 有効化**（Stripe Dashboardの設定のみ、実装不要） |
| 課金ページ | 汎用 | Checkout の商品名を「FOLLOW 月額サポート（いつでも解約OK）」に、880円/月を明示 |
| 離脱 | 追跡なし | Checkout セッション期限切れ（離脱）を Webhook で捕捉 → 24時間後に川崎さんから一言フォロー |

#### S-3. 初月無料A/Bテスト — 7月中旬開始（I-abtest 設計済みの実行）
- A群: 初月から880円 / B群: **初月無料（trial_period_days=30）+ カード登録必須**
- 振り分け: uid末尾偶奇
- 判定: B群CVRがA群+15pt以上 かつ 2ヶ月目継続率70%以上で採用
- Stripe実装: Subscription 作成時に `trial_period_days: 30` を付けるだけ。Dに実装Issue起票 → CODEX対応
- 原価リスクほぼゼロ（商材はアフィリエイト型、川崎稼働は既存範囲）

#### S-4. 紹介プログラムの Stripe 実装 — 7月下旬（28名キャンペーンAグループの受け皿）
```
紹介発生 → Stripe Coupon「1ヶ月無料」を紹介者・被紹介者の両方に適用
→ 実装: Coupon (duration: once, percent_off: 100) + Referral URL に UTM
→ 7/2開始の28名キャンペーンでグループAから紹介が出る前に用意
```
- 暫定運用（リンク未実装の間）: 「◯◯さんの紹介」と一言 → 川崎さんが手動でCoupon適用（H-28campaign-SEND-2026-07.md に記載済み）

#### S-5. 解約→休止への転換 — 7月中
- 解約申し出時に「休止」を第一選択肢として提示（28名キャンペーンCグループ文面に組込み済み）
- Stripe実装: `pause_collection` で請求停止・データ保持
- 復帰オファー: 休止30日後に1回だけ（それ以上追わない）

#### S-6. Stripe Webhook → KPI自動集計 — 8月
```
checkout.session.completed / customer.subscription.deleted /
customer.subscription.paused → Workers or GAS 経由で FOLLOW-KPI シートに自動記録
→ F の日次レポートに「今日の新規課金・解約・休止」が載る
```

#### S-7. カウンセリングフォーム短縮 — 8月（登録→カウンセリング26%対策）
- 質問数を半分に（3分→1.5分）
- リマインダー3段: 3時間 / 24時間 / 1週間（既存Bot設計に追加）
