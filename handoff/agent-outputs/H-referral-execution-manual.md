## 1. 紹介リンク発行のフロー

### 1-A. 実装前の暫定運用（〜D実装完了まで）

**コンセプト**：システムがないので、川崎さんの「手動・台帳ベース」で運用する。これでも28名規模なら回る。

#### Step 1：紹介依頼の送信を決める（川崎担当）

- H-28campaign-final.md のグループA文面を使う
- 候補：継続3ヶ月以上 + 月1回以上相談 + ポジティブ反応歴
- 1日3名まで送信（押し付け感の回避）

#### Step 2：返信で「紹介したい」が返ってきた（川崎担当）

下記の代替テンプレを送る：

```
{name}さん、ありがとうございます。
本当に嬉しいです。

今、紹介の専用リンクを準備中なのですが、
それまでの間はお知り合いの方に、
私のLINE ID「@follow-kawasaki」を直接お伝えください。

そのとき「{name}さんからの紹介」と一言添えていただければ、
こちらで紹介としてお受けします。

おふたりとも1ヶ月無料になります。
お知り合いの方が登録された後、{name}さんに改めてご報告しますね。

― 川崎
```

#### Step 3：紹介台帳に記録（川崎担当 + H共同）

スプレッドシート `referral-log-2026.gsheet` を作成（Hが雛形提示）。

| 列名 | 内容 | 例 |
|---|---|---|
| referral_id | 連番 | R-001 |
| 紹介者名 | 川崎さんが入力 | 田中さん |
| 紹介者LINE名 | LINE表示名 | tanaka_yuki |
| 紹介依頼日 | 送信日 | 2026-06-18 |
| 返信日 | 「紹介したい」と返ってきた日 | 2026-06-20 |
| 被紹介者名 | LINE登録時に確認 | （未） |
| 被紹介者LINE登録日 | LINE Botに来た日 | （未） |
| カウンセリング完了日 | LINE上で完了確認 | （未） |
| 初月課金日 | Stripe確認 | （未） |
| 紹介者への報酬付与日 | 次回課金スキップ実施日 | （未） |
| ステータス | pending / completed / cancelled | pending |
| メモ | 経緯・トラブル等 | |

#### Step 4：被紹介者がLINE登録（H担当）

LINE Botは「紹介者名」をヒアリングする自動応答を持つ：

```
はじめまして、FOLLOWの川崎です。
ご登録ありがとうございます。

差し支えなければ、どなたのご紹介か教えてください。
お友達のお名前 or LINE名で結構です。
（紹介でない方は「なし」とお答えください）
```

→ 回答が来たら川崎さんに通知 → 台帳に追記

#### Step 5：初月課金完了の確認（川崎担当）

- Stripe Dashboard で被紹介者の初回課金が成功したことを確認
- 台帳の「初月課金日」を記入
- ステータスを `completed` に変更

#### Step 6：紹介者への報酬付与（川崎担当・1-Cで詳述）

→ Stripe で次回課金をスキップ（後述 §3 参照）
→ 紹介者にLINE通知（後述 §2-C）

### 1-B. 実装後の自動化フロー（D実装完了後）

#### 自動化される範囲（D Issue化済み）

- 招待コード自動生成（管理画面から発行）
- LP の「◯◯さんから紹介」表示
- 被紹介者課金完了 → 紹介者へ次回課金スキップ自動付与
- 管理画面の紹介ダッシュボード
- LINE Bot から紹介リンク自動送信

#### 川崎さんがやること（実装後）

1. 管理画面で対象顧客の「紹介リンク発行」ボタンを押す
2. 自動生成された `https://follow.app/r/{8桁コード}` を含む依頼文面が出る
3. LINE Botの「下書き送信」ボタンを押す → 川崎さんが内容確認 → 送信
4. 以降は全自動。紹介者には「ありがとう」LINEが自動配信される

#### Hがやること（実装後）

- 候補抽出を週次でDashboardに出す
- 発行されたリンクのクリック率・CV率を集計
- 異常検知（不自然な大量登録など）

## 3. Stripe処理手順（1ヶ月無料適用）

### 3-A. 暫定期（手動）

#### 紹介者の次回課金スキップ手順

1. Stripe Dashboard → Customers → 紹介者のメールで検索
2. 該当顧客の Subscription を開く
3. 「Actions」→「Update subscription」
4. 「Coupons」セクションで以下のいずれか：
   - **方法A（推奨）**：事前に作成しておいた `REFERRAL_1MONTH_FREE` クーポン（duration: once, amount_off: ¥880）を適用
   - **方法B**：次回請求日を1ヶ月後ろにずらす（Trial end の変更）

5. 「Update subscription」で保存
6. 顧客に確認LINE（§2-C の文面）を送信
7. 台帳の「紹介者への報酬付与日」を入力

#### 被紹介者の初月無料適用

**LP/LINE登録経由**：既存の「初月無料キャンペーン」フローでそのまま課金処理（実装済）
→ Stripe 上は trial_period_days=30 のサブスクリプションとして作成される

#### 失敗時のリカバリ

| 状況 | 対応 |
|---|---|
| クーポン適用したがエラー | 次回請求日変更（Trial end）にフォールバック |
| 紹介者がすでに次月分課金済み | 次々月をスキップに変更（顧客に説明LINE） |
| クーポンコード入力漏れ | Hが日次レポートで検知 → 翌営業日にリカバリ |

### 3-B. 実装後（自動）

D実装で Stripe Webhook 経由：

```
被紹介者 invoice.payment_succeeded（初回）
→ FOLLOWバックエンドが referral_log を確認
→ 紹介者の subscription に REFERRAL_1MONTH_FREE クーポン自動適用
→ LINE Bot から紹介者へ報告メッセージ自動送信
→ 台帳（DB）の status を completed に
```

川崎さん側の手動操作はゼロ。確認は月次レポート（§5）で。

### 3-C. クーポン作成（一度だけやる）

Stripe Dashboard → Products → Coupons → New：

```
ID: REFERRAL_1MONTH_FREE
Type: Amount off
Amount: ¥880
Duration: Once
Currency: JPY
Max redemptions: なし（無制限）
```

## 4. トラブル対応プレイブック

### 4-A. 紹介者と被紹介者の関係性が崩れた場合

**シナリオ例**：紹介後に二人が喧嘩、被紹介者が「紹介者の名前を出してほしくない」

**対応フロー**：
1. 川崎さんが両者と個別にLINEで状況確認
2. 紹介関係を「ペーパー上は維持、表に出さない」運用に切替
   - 報酬（1ヶ月無料）は約束通り双方に付与
   - §2-C の報告LINEで紹介者名を出さないバージョンに切替：
   ```
   {紹介者name}さん、ご紹介ありがとうございました。
   無事にご登録・初月課金が完了しましたので、
   {name}さんの次回課金は1ヶ月分スキップとなります。
   ```
3. 台帳の「メモ」欄に経緯を記録
4. 以降、紹介者にこの被紹介者の話題を出さない

### 4-B. 紹介者と被紹介者が同一人物のなりすまし疑い

**検知サイン**：
- 同じデバイスID / IPアドレスでの登録
- 名前・住所の不自然な一致
- 紹介者のLINE登録から24時間以内の被紹介者登録

**対応**：
1. Hがアラートを上げる
2. 川崎さんが両アカウントに本人確認の連絡
3. なりすまし確定なら紹介報酬は不付与、両アカウントを警告
4. ただし疑わしいだけなら「決め打ちしない」、まず聞く

### 4-C. 紹介された人がすぐ解約した

**ルール**：初月課金が完了していれば紹介報酬は維持（仕様 §2-4 通り）。
→ ただし「初月課金 → 即日解約」が連続する場合は不正の可能性、Hがアラート。

**川崎さんの対応**：
- 通常通り解約処理
- 紹介者に対しては何も特別なことは言わない（「紹介された人が辞めました」を伝えない）
- 報酬は予定通り付与

### 4-D. 紹介依頼への強い拒否反応

**シナリオ**：「人にすすめるとかしたくない」「マルチみたいで嫌」

**対応**：
1. 即座に謝罪：
```
{name}さん、不快な思いをさせて申し訳ありません。
お声がけ自体が見当違いでした。
今後このようなお声がけは一切いたしません。

これまで通り、{name}さん個人のサポートに集中させてください。
― 川崎
```
2. `referral_opt_out: true` + `do_not_ask_again: true` をフラグ付与
3. Hが同様パターンの兆候を持つ他顧客への送信を一時停止 → 文面見直し

### 4-E. 紹介者が報酬付与漏れを指摘

**対応フロー**：
1. 即座に謝罪 + 状況確認の時間をもらう
2. 台帳・Stripeログを照合
3. 不付与だった場合：即時クーポン適用 + お詫びとして次月もスキップ（合計2ヶ月無料）
4. 仕組み側の問題なら Hが Issue化 → D に共有

### 4-F. 「金銭で報酬欲しい」と言われた

**対応**：
```
{name}さん、ありがとうございます。
お気持ちは嬉しいのですが、現金や金券での還元はお受けしていません。
紹介プログラムは、サービスを実際に使ってくださる方への
「次回無料」という形だけ、と決めています。

― 川崎
```

→ MLM誤認回避のため、現金還元は絶対にやらない（E法務観点）。

## 6. 法務（E）チェック観点

毎月のレポート発行時 + 文面更新時に Hがセルフチェック。違反疑いがあれば E にエスカレ。

### 6-A. 金銭表示なし

**NG例**：
- 「紹介で880円バック」
- 「現金還元あり」
- 「友達紹介で◯◯円もらえる」

**OK例**：
- 「おふたりとも1ヶ月分が無料」
- 「次回課金がスキップ」
- 「初月無料」

→ 「無料」「割引」「スキップ」のみ使用。「円」「現金」「キャッシュ」「ポイント」は禁止。

### 6-B. MLM誤認なし

**NG例**：
- 「紹介すればするほど得」
- 「広めてください、収入になります」
- 「ダウンライン」「アップライン」など連鎖性を匂わせる語

**OK例**：
- 「もしよかったら」
- 「気が向いたときだけで」
- 「紹介しなくても対応は変わりません」

**仕組み面でのMLM防止**：
- 多段階報酬なし（A→B→Cで紹介してもAには何も発生しない）
- 紹介数の上限（年6回）を設定
- 金銭報酬なし（次回無料のみ）

### 6-C. 押し付けなし

**NG例**：
- 「ぜひ紹介してください」
- 「今月中に！」「今だけ」
- 紹介依頼の連続送信

**OK例**：
- 「もしよかったら」「気が向いたら」
- 「無理にとは言いません」
- 「紹介しても、しなくても、対応は変わりません」

**運用ルール**：
- 1顧客への紹介依頼は生涯3回まで（半年に1回ペース）
- 1回断られたら opt_out フラグ、二度と聞かない
- 無反応は無反応として尊重、追撃禁止

### 6-D. その他チェック

- 景表法：報酬条件をLP / 利用規約に明記
- 特商法：返金条件・契約条件を明記
