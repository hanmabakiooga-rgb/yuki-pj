## 3. データ集計ロジック

### 3-1. 相談件数
```sql
SELECT COUNT(*) FROM messages_log
WHERE direction = 'outbound'
  AND sender = 'kawasaki'
  AND DATE(created_at) = DATE('now', 'localtime');
```

### 3-2. 平均応答時間
```sql
SELECT AVG(
  (kawasaki_reply_at - customer_message_at) / 60
) FROM message_pairs
WHERE DATE(customer_message_at) = DATE('now', 'localtime');
```

### 3-3. 連続稼働日数
```sql
SELECT COUNT(DISTINCT DATE(created_at)) FROM messages_log
WHERE sender = 'kawasaki'
  AND created_at >= DATE('now', '-7 days', 'localtime');
```

### 3-4. 警告判定

| メトリック | 警告条件 |
|---|---|
| 連続稼働 | **6日連続**で警告 |
| 日次件数 | **25件超**で警告 |
| 応答時間 | **4時間超**で警告 |
| 営業時間外 | **24時間で5件超**で警告 |

## 5. スケール判断ロジック

### 5-1. 顧客数別の警告レベル

| サブスク数 | 状態 | アクション |
|---|---|---|
| 0〜100 | 余裕 | - |
| 100〜130 | 注意 | カラーリスト2人目候補のリストアップ開始 |
| 130〜150 | 警告 | カラーリスト2人目の採用準備本格化 |
| 150〜180 | 危険 | 新規受付一時停止を検討 |
| 180〜 | 限界 | 即時新規停止、過去問い合わせ対応のみ |

### 5-2. 川崎さん1人で持てる上限

仮置き：**150名**（運用しながら校正）。

参考算定：
- 1顧客あたり月3回相談、5分応答 = 15分/月
- 150人 × 15分 = 2,250分/月 = 約100時間/月
- 平日5時間×20日 = 100時間 → 限界
- 余裕を見て120〜130名で2人目検討開始

## 6. 自動応答ルール（営業時間外）

| 時間帯 | 対応 |
|---|---|
| 平日 9:00-19:00 | 川崎さん個別（Bot補助あり）|
| 平日 19:00-22:00 | Bot「翌営業日返信」案内 + 緊急ワードのみエスカレ |
| 平日 22:00-翌9:00 | Bot のみ |
| 土日祝 | Bot のみ |

緊急ワード：「頭皮 痛い」「染料 入った 目」「腫れた」「アレルギー 出た」「血」  
→ J が即時 H・B 起動 + ユーザーLINEへ警告
