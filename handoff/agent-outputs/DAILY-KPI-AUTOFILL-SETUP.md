# KPI daily「投稿数」自動記入 — ローカル投入手順書

作成日: 2026-07-14
対象コード: `handoff/agent-outputs/gas-code/DailyKpiFill.gs`
実行者: ローカルセッション（Claude Desktop / ブラウザでGASエディタを操作できる人）
想定所要時間: 20〜30分（§4-5の翌日確認を除く）

---

## §0 目的と効果

- GO/NOGOチェック D-2「dailyシートに数値が入っている」のうち、**「投稿数」列だけを自動化**する（2026-06-27〜昨日分のバックフィル＋毎日0:30 JSTの自動追記）。
- これにより手動KPI運用の負荷が1列分減り、D-2が「全期間空欄」状態から脱する。
- **スコープ外**: LINE登録数・新規LINE・サブスク数・解約・広告費・CPA・CVRなどの他列は**今回は手動のまま**。この手順書では一切触らない。

## §1 投入前チェック（必ず全部やってから§2へ）

正しい貼り付け先は、スタンドアロンGASプロジェクト **「FOLLOW Threads Autopost」** です。

1. ブラウザで https://script.google.com を開き、プロジェクト一覧から **「FOLLOW Threads Autopost」** をクリックして開く。
   - プロジェクトID（URLに含まれる文字列）が `1fU3cSi8Y4pmghGID5BFHphlUfB1Yi3AamWRN1QMpQz08gqDWIOjIyWC7` であればなお確実。
2. 左のファイル一覧に **`Main.gs` / `Config.gs` / `ContentGenerator.gs`** が並んでいることを確認する（＝Threads自動投稿の本体）。
3. `Config.gs` を開き、`SPREADSHEET_ID` が FOLLOW-KPIスプレッドシートのID（`1Xshvq…` で始まる）と一致していることを確認する。これが「このGASがKPIシート（FOLLOW KPI）に書き込む本番プロジェクトである」証拠。

🚫 **落とし穴**: FOLLOW-KPIスプレッドシートから「拡張機能 → Apps Script」で開くと、**中身が空の別プロジェクト（バインドプロジェクト）** が出てきます（SESSION-PROGRESS-2026-07-12で確認済みの罠）。**ファイル一覧が空、またはMain.gsが無い画面が出たら、それは貼り付け先ではありません。** 閉じて手順1からやり直してください。

### 1-2. `listAllKpiTabs()` でタブ構成を確認する（副作用なしの診断）

このプロジェクトには診断用関数 `listAllKpiTabs()` が含まれます（§2でコードを貼った後に実行しますが、**§3の本実行の前に必ずこれを先に実行**します）。読み取り専用でシートは一切変更しません。

- **「daily」タブの実際の名前（大文字小文字・前後スペース含む）はここで判明します。** ログに daily 相当のタブが見えない場合は、§3に進まず作業を中断し、状況を報告してください。

## §2 投入手順（新規ファイルとして追加。既存ファイルには触らない）

⚠️ **`Main.gs`・`Config.gs`・`ContentGenerator.gs` など既存ファイルは一切編集しない**こと。今回は新規ファイルの追加のみです。

1. §1-1で開いた「FOLLOW Threads Autopost」のGASエディタで、左のファイル一覧の上にある **「＋」ボタン → 「スクリプト」** をクリック。
2. ファイル名の入力欄に `DailyKpiFill` と入力してEnter（`.gs` は自動で付く）。
3. 新しいファイルが開いたら、中に最初から入っている `function myFunction() {…}` を**全部選択して削除**する。
4. 手元の `handoff/agent-outputs/gas-code/DailyKpiFill.gs` の中身を**全文コピーして貼り付け**る。
5. 上部の **保存アイコン（フロッピー）** をクリック（またはCtrl+S / Cmd+S）。
6. 赤いエラー表示が出ないこと、上部の関数選択ドロップダウンに以下の5関数が現れることを確認する：
   - `listAllKpiTabs` / `fillDailyPostCounts` / `fillDailyPostCountsDaily` / `installDailyKpiTrigger` / `uninstallDailyKpiTrigger`

## §3 実行手順（この順番厳守）

> ### 🚨 全ステップ共通・最重要の注意
> **実行ボタンを押す直前に、関数選択ドロップダウンが「今から実行したい関数名」になっているかを毎回必ず目視確認してください。**
>
> 過去の実物の事故（SESSION-PROGRESS-2026-07-12より引用）:
> 「GASエディタの関数選択が startCampaign500 に確定せず、誤って `seedTemplates()` を実行。`sns_templates` に21テンプレの重複行が追加された」— 最終的に**本番シートに重複42行**が作られ、ユーザー承認を取った上での削除クリーンアップが必要になりました。
> さらに同記録には「**関数選択ドロップダウンの挙動（Escapeで選択が巻き戻る）** により smokeTest が2回余分に実行された」ともあります。**ドロップダウンでEscapeキーを押すと選択が前の関数に戻ることがある**ため、「選んだつもり」を信用せず、**押す直前の表示名を読む**こと。

### Step 1: `listAllKpiTabs` を実行（タブ構成の確認）

1. ドロップダウンで `listAllKpiTabs` を選択。
2. **押す直前にドロップダウンの表示が `listAllKpiTabs` であることを目視確認**してから「実行」をクリック。
3. 初回は権限承認画面が出るので、自分のGoogleアカウントで「許可」する。
4. 画面下の「実行ログ」に全タブ名が出る。**daily相当のタブ名を確認**する。dailyタブが見つからなければここで中断。

### Step 2: `fillDailyPostCounts` を実行（バックフィル）

1. ドロップダウンで `fillDailyPostCounts` を選択。
2. **押す直前にドロップダウンの表示が `fillDailyPostCounts` であることを目視確認**してから「実行」をクリック。
3. 実行ログにエラーが無いことを確認。
4. **FOLLOW-KPIスプレッドシートのdailyタブを開き、目視確認**する：
   - 2026-06-27以降、昨日までの各行の「投稿数」列に数字が入っている。
   - 「投稿数」列**以外**（LINE登録数など）は空欄のまま／元の値のまま（コードは手入力値を上書きしない仕様だが、念のため見る）。

### Step 3: `installDailyKpiTrigger` を実行（毎日0:30 JSTトリガー設置）

1. ドロップダウンで `installDailyKpiTrigger` を選択。
2. **押す直前にドロップダウンの表示が `installDailyKpiTrigger` であることを目視確認**してから「実行」をクリック。
3. 左メニューの **時計アイコン（トリガー）** をクリックし、トリガー一覧に **`fillDailyPostCountsDaily`（時間ベース・毎日 午前0時〜1時ごろ）** が**1件だけ**あることを確認する（この関数は冪等設置なので、複数回実行しても重複はしない仕様。もし2件以上あれば報告）。
4. ついでに既存の運用トリガー（`generateTomorrowPosts` / `checkAndPost` / `killSwitchHealthCheck` 等）が**消えていない**ことも確認する。

## §5 ロールバック（問題が起きたら）

影響範囲はKPIシートの「投稿数」列とトリガー1本のみで、**Threads自動投稿・LINE Bot・LP等の他システムへの影響はゼロ**です。戻すのは次の2つだけ：

1. GASエディタでドロップダウンから `uninstallDailyKpiTrigger` を選択（**押す直前に表示名を目視確認**）→「実行」→ トリガー一覧から `fillDailyPostCountsDaily` が消えたことを確認。
2. dailyタブの「投稿数」列に自動記入された値を、手でセルを選択して削除する（手入力していた値があればそれは残す）。

必要なら `DailyKpiFill.gs` ファイル自体を削除してもよい（左のファイル一覧でファイル名右の「︙」→「削除」）。既存コードには手を入れていないので、これで投入前と完全に同じ状態に戻ります。
