# RESERVA → Googleカレンダー自動登録

RESERVA（`noreply@reserva.be`）から届く「予約が入りました」通知メールを解析し、
「予約者の氏名」「予約内容（メニュー）」「予約日時」をGoogleカレンダーの予定として自動登録するGoogle Apps Scriptです。

## 関数一覧

| 関数 | 用途 | 実行タイミング |
| --- | --- | --- |
| `syncReservaToCalendar` | メール解析→カレンダー登録の本体 | トリガーで5分おき |
| `markExistingAsProcessed` | 既存メールにラベルを付けるだけ（予定は作らない） | 導入時に1回 |
| `createTrigger` | 5分おきの定期実行トリガーを登録 | 導入時に1回 |
| `syncSingleForVerification` | 重複でない予約を1件だけ実際に登録する動作確認用 | 必要時 |
| `listTriggers` | 登録済みトリガーの確認 | 必要時 |

## セットアップ手順

1. [script.google.com](https://script.google.com) で新しいプロジェクトを作成し、`Code.gs` の内容を貼り付ける。
   マニフェスト（`appsscript.json`）も本リポジトリの内容に合わせる。タイムゾーンが
   `Asia/Tokyo` でないと予定の時刻がずれるので必ず確認すること。
2. `DRY_RUN = true` のまま `syncReservaToCalendar` を手動実行する。
   - 初回はGmail・カレンダーへのアクセス許可を求められるので承認する。
   - **この状態ではカレンダーに一切書き込まない。** 「何件・どの予定を作ろうとしているか」が実行ログに出るだけ。
   - ログを読み、意図した予約だけが対象になっているかを確認する。
3. `markExistingAsProcessed` を1回実行する。
   - 受信箱に残っている既存のRESERVAメール全部にラベルを付け、処理済みとして寝かせる。
   - **これを省くと、導入時に過去の予約が一気にカレンダーへ流れ込む。** 手順の中で最も重要。
4. `DRY_RUN = false` に変更する。
5. `createTrigger` を1回実行し、`listTriggers` で「1件」になっていることを確認する。

## 動作の仕組み

- 検索対象: `from:noreply@reserva.be subject:予約が入りました` に一致するメール
- 処理済みのメールスレッドには `RESERVA登録済み` ラベルを付与し、次回以降の重複登録を防ぐ
- 登録先はスクリプト実行アカウントのデフォルトカレンダー（`CalendarApp.getDefaultCalendar()`）
- 予定タイトルは `氏名様 - メニュー`、開始/終了時刻はメール本文の「■予約日時」欄から設定
- メール受信日より60日以上過去の日付になった場合は年またぎ予約とみなし、翌年の日付として登録
- 5分おきにGmailを検索するポーリング方式。未処理メールが無いときは即座に抜けるため、
  空振り時の実行時間はごくわずか（1日288回でも合計5分程度、GASの上限90分/日に対して十分な余裕）

### 重複登録の防止

Gmailラベルによる「同じメールを二度処理しない」制御に加えて、カレンダー側も確認する。
手入力やLINE予約ボットで既に同じ予約が入っている場合に二重登録しないため、
次のいずれかに当てはまる予定が既にあれば登録をスキップする。

1. 開始時刻が一致する予定が既にある
2. 時間帯が重なっていて、タイトルに予約者名（またはその姓）が含まれる

1を「開始・終了の両方一致」にしていないのは、手入力側がメニューの標準時間ではなく
実際の施術見込みで終了時刻を入れており、開始は一致するが終了はずれるケースが実データで大半だったため。

2の名前一致は、漢字表記（RESERVA）とひらがな・愛称表記（手入力）が食い違うとすり抜ける。
あくまで1の補助。

名前が一致しない時間帯の重なりは、別客のダブルブッキングの可能性があるためスキップせず、
登録したうえでログに警告を残す。

## 制限事項

- **キャンセル・日時変更に対応していない。** 拾うのは件名「予約が入りました」のみなので、
  予約がキャンセル・変更されてもカレンダーの予定は残り続ける。当面は手動で修正する必要がある。
- 同じ開始時刻に別の客を入れた場合、重複とみなされて登録されない（ログには残る）。
- メール本文の書式にRESERVA側の仕様変更があると解析が失敗する。
  失敗時は件名付きでログに残るが、通知はされない。

## カスタマイズ

- `Code.gs` 冒頭の `RESERVA_LABEL_NAME` / `RESERVA_SEARCH_QUERY` で検索条件・ラベル名を変更可能
- 登録先カレンダーを変更したい場合は `CalendarApp.getDefaultCalendar()` を
  `CalendarApp.getCalendarById('カレンダーID')` などに置き換える
- 実行間隔は `createTrigger()` 内の `everyMinutes(5)` で変更する
  （指定できるのは 1・5・10・15・30 のいずれか。`createTrigger` は既存トリガーを消してから
  作り直すため、何度実行してもトリガーは1つに保たれる）

## OAuthスコープ

`appsscript.json` で以下を指定している。

| スコープ | 用途 |
| --- | --- |
| `gmail.modify` | 通知メールの検索・本文取得・ラベル付与 |
| `calendar` | 予定の作成、および既存予定の確認 |
| `script.scriptapp` | トリガーの登録・削除 |

カレンダーは `calendar.events` では足りない。`getDefaultCalendar()` がカレンダー一覧を
参照するため、`calendar` が必要になる。
